This site has no framework

2026-11-12 Web Tools

A personal site does not need a build pipeline. This one is a handful of static pages, a theme stylesheet, three icon fonts, and one small script. GitHub Pages serves it directly, which means there is nothing between saving a file and seeing it online.

The whole stack

  • HTML for the pages, with the cover layout borrowed from the Vno theme;
  • CSS for the dark overlay, the green accents, and the two-column resume/blog layout;
  • About twenty lines of JavaScript: rotate the background once per session, toggle the mobile menu;
  • A JSON file listing the background images.

The background logic is the only stateful part, and it is short enough to paste here:

var index = (isNaN(stored) ? 0 : stored + 1) % imgUrls.length;
target.style.background = "url('https://www.bing.com" + imgUrls[index] + "') center center no-repeat #666";

What I removed

An old audit turned up the usual archaeology: a webfont loaded but never used, a duplicated background script on the resume page, an unused script block with timer helpers nobody called, and images that were several times larger than they displayed. Compression alone took the image payload from about 1.4 MB to roughly 130 KB.

The 404 page now uses root-absolute asset paths, so a wrong URL at any depth still gets the correct styles instead of a naked page.

What it costs

Almost nothing. There is no dependency to upgrade and no configuration to debug. Adding a post means copying one HTML file and editing it; adding a page means the same. When the site outgrows that, it will be a good problem and a deliberate decision — not a default.
